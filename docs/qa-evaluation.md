# 소규모 QA 평가 세트와 자동 실행기

`qa-small-v1`은 현재 엔진이 지원하는 합성 웹앱 12개 사례를 평가한다. **공개된 개발용 평가 세트**이며 실제 고객사 서비스의 정확도나 미공개 벤치마크 점수를 의미하지 않는다. 엔진/프롬프트 개선 후에는 별도 미공개 사례로 일반화를 확인해야 한다.

## 평가 사례

| 사례 ID | 대상 | 기대 결과 |
|---|---|---|
| `search_bug` | 결과가 없는 검색에서 이전 결과가 남음 | 재현됨 |
| `search_normal` | 같은 제보를 정상 검색 구현에서 확인 | 재현 안 됨 |
| `filter_bug` | 필터 초기화 뒤 필터된 결과가 남음 | 재현됨 |
| `filter_normal` | 같은 제보를 정상 필터 구현에서 확인 | 재현 안 됨 |
| `clipping_bug` | 상품 제목의 오른쪽 텍스트가 잘림 | 재현됨 |
| `clipping_normal` | 같은 제보를 정상 너비에서 확인 | 재현 안 됨 |
| `overlap_bug` | 두 페이지 이동 버튼이 겹침 | 재현됨 |
| `overlap_normal` | 같은 제보를 정상 배치에서 확인 | 재현 안 됨 |
| `missing_expectation` | 문제 설명 없는 정상 계정 화면 이미지 | 추가 질문 |
| `missing_search_data` | 검색어·대상 데이터가 없는 제보 | 추가 질문 |
| `environment_unavailable` | 테스트 대상이 HTTP 503 반환 | 환경 장애로 검증 보류/실패 |
| `environment_unauthorized` | 테스트 대상이 HTTP 401 반환 | 접근 실패로 검증 보류/실패 |

버그/정상 쌍은 **같은 제보 텍스트와 같은 버그 화면 이미지**를 사용한다. 정상 사례는 이미 수정된 대상에 과거 제보를 검증하는 상황이다. 이는 일반적인 정상 스크린샷 분류 평가와 다르다. 모든 사례에서 제출 텍스트에 적힌 기대 동작은 정당한 입력으로 유지한다.

화면 제목은 상품 검색·상품 안내 같은 일반 이름이다. 대상 URL은 매 실행 생성한 무작위 경로이며 `bug/fixed/control`이나 정답 레이블을 포함하지 않는다. 버그/정상 전환은 서버 메모리에서만 수행한다. 모델에는 제보·정제된 관찰·이미지·엔진 계약만 제공하고 사례 ID, 정답, reference plan, 독립 채점 결과를 보내지 않는다.

## 실행 방법

저장소 루트에서 실행한다. 기존 브라우저 추가 의존성과 Chromium 설치가 필요하다. 소스를 수정한 뒤 재설치하거나 아래처럼 `PYTHONPATH=src`를 사용한다.

사례 목록:

```bash
PYTHONPATH=src python -m core_engine.evaluation --list
```

키 없이 고정 모델로 평가기 자체를 검증:

```bash
PYTHONPATH=src python -m core_engine.evaluation --repeats 1 --retest-fixed
```

이 모드는 실제 Chromium과 독립 검사기를 사용하지만 모델 응답은 미리 준비되어 있다. 보고서에 **고정 모델 연결 검증 — AI 성능 점수 아님**으로 표시된다. 이 성공률을 AI 성능으로 발표하면 안 된다.

서버에 `OPENAI_API_KEY`, `OPENAI_MODEL`을 설정한 후 실제 모델 평가:

```bash
PYTHONPATH=src python -m core_engine.evaluation --live --repeats 3 --retest-fixed
```

로컬에서 직접 작성한 `.env`를 사용할 경우 먼저 명시적으로 불러온다. 파일 내용이나 키를 콘솔에 출력하지 않는다.

```bash
set -a
source .env
set +a
PYTHONPATH=src python -m core_engine.evaluation --live --repeats 3 --retest-fixed
```

두 사례만 적은 호출 수로 확인:

```bash
PYTHONPATH=src python -m core_engine.evaluation --live \
  --case search_bug --case search_normal --repeats 1 --max-model-calls 10
```

| 옵션 | 기본값과 의미 |
|---|---|
| `--live` | 생략하면 고정 모델. 지정하면 실제 유료 모델 호출 |
| `--repeats` | 3회. 1~10회 허용 |
| `--case` | 생략하면 12개 전체. 여러 번 지정하여 선택 가능 |
| `--seed` | 17. 사례 실행 순서의 무작위화만 고정하며 모델의 샘플링 결과를 고정하지 않음 |
| `--max-model-calls` | 평가 전체 공급자 호출 상한 120회. HTTP 자동 재시도 없음 |
| `--retest-fixed` | 독립 검사까지 통과한 버그 작업을 정상 버전에서 동일 계획으로 추가 검증 |
| `--output` | `.qa-evals`. 실행마다 새 디렉터리를 만들어 과거 결과 보존 |

전체 3회 반복은 최초 작업 **36개**, `--retest-fixed` 사용 시 비교 항목 **12개**다. 기준 버그 재현에 실패한 항목은 재검증 호출을 하지 않고 `BASELINE_NOT_CONFIRMED`로 실패 집계한다. 성공한 기준만 분모로 삼아 수정 확인 성공률을 부풀리지 않는다.

전체 호출 상한에 도달하면 진행 중 작업은 엔진의 `MODEL_CALL_LIMIT`으로 처리하고 나머지는 `not_run/EVAL_MODEL_CALL_LIMIT`으로 남긴다. `Ctrl+C`는 종료 코드 130이며, 이미 저장된 결과는 유지된다. 키·설정 누락은 호출 전에 거절한다.

종료 코드 0은 계획한 항목의 채점이 모두 통과했다는 뜻이다. 1은 실패 항목 또는 미실행이 있다는 뜻이며, 실제 AI 평가에서는 정상적인 측정 결과일 수 있다. JSON의 `complete`, `harness_errors`, `valid_for_comparison`을 함께 확인한다.

## 독립 채점 방식

1. 평가기만 아는 reference plan으로 제보 이미지를 실제 브라우저에서 만든다. 여기서 의도한 증상이 나오지 않으면 평가기 오류다.
2. 대상 버전을 설정하고 새 `QAService`에 제보를 전달한다. AI가 직접 intake·계획·보고서를 생성한다.
3. 버그/정상 사례에서 확정 판정이 나오면 **AI가 생성한 동일 계획을 새 브라우저에서 다시 두 번 실행**한다.
4. 모델에 전달하지 않는 별도 검사기가 테스트용 서버의 조작 이력과 실제 DOM 상태를 확인한다.
5. 원래 판정, 독립 실행 완료, 실제 의도한 증상/정상 상태가 모두 맞을 때 통과한다.

검색 사례는 상품 검색 후 없는 검색어를 입력했는지, 필터 사례는 필터 적용 후 초기화했는지 조작 이력으로 확인한다. 검색 한 번만 해서 결과가 남아 있는 것을 버그라고 한 경우에는 판정 문자열이 맞아도 실패한다. 시각 사례는 실제 텍스트 영역 크기 또는 두 버튼의 좌표 교차를 검사한다.

평가기의 판정은 모델이 작성한 설명을 다른 모델에게 다시 읽혀 얻지 않는다. 독립 채점 결과를 이용해 같은 실행 중 AI 계획을 고치지도 않는다. 다만 브라우저 실행·전송은 기존 엔진의 범위 통제를 공유하므로, 완전히 독립된 두 브라우저 구현을 비교하는 것은 아니다.

정보 부족 사례는 `needs_info`와 실제 질문의 존재, 확정 재현 판정이 없는지를 검사한다. **질문의 구체성·유용성은 자동 채점하지 않는다.** `results.json`의 질문을 사람이 검토해야 한다.

환경 장애 사례는 실제 401/503 접근 기록과 `HTTP_ERROR/NAVIGATION_FAILED`를 확인한다. 모델 인증 오류·모델 타임아웃·막연한 질문을 환경 장애 정답으로 인정하지 않는다.

## 지표와 해석

| 지표 | 분자 / 분모 |
|---|---|
| `reproduction_success` | 독립 검사까지 통과한 버그 작업 / 시작한 버그 작업 |
| `normal_success` | 독립 검사까지 통과한 정상 대상 작업 / 시작한 정상 대상 작업 |
| `false_positive` | 정상 대상에 `reproduced`를 반환한 작업 / 시작한 정상 대상 작업 |
| `conclusive_coverage` | 확정 재현 판정이 나온 작업 / 시작한 버그·정상 대상 작업 |
| `question_routing` | 추가 질문 분기를 올바르게 사용한 작업 / 시작한 정보 부족 작업 |
| `environment_handling` | 실제 환경 장애를 식별한 작업 / 시작한 환경 장애 작업 |
| `fixed_pair_success` | 같은 계획으로 버그 재현과 수정 확인 모두 통과 / 선택한 버그 비교 항목 전체 |

시작한 작업의 보류·모델/엔진 실패는 성공에 포함하지 않고 분모에는 포함한다. 미실행은 별도로 표시하며, 일부만 실행한 결과를 전체 점수로 사용하지 않는다. 평가기 자체 오류가 있으면 `valid_for_comparison=false`다. 고정 모델 결과도 항상 이 값이 false다.

오탐률만 보면 모든 입력을 보류하는 모델이 좋아 보일 수 있으므로 판정 완료율·정상 판정 성공률을 함께 본다. 12개 사례의 반복 3회는 독립적인 사례 36개가 아니다. 이 실행기로 프롬프트를 조정한 후 같은 사례에서 얻은 점수는 개발 세트 결과로 표시한다.

QA 실행 시간은 `QAService.run/retest` 호출부터 반환까지 측정하며 제보 이미지 준비·평가기 독립 재실행 시간은 포함하지 않는다. 공급자 호출별 시간과 입력/출력 토큰도 저장한다. 사용량을 반환하지 않은 호출은 `null`로 남기고 별도로 집계한다. 실제 과금 세부 정보를 얻지 못하므로 USD 비용을 추정하여 채워 넣지 않는다.

원인 가설·해결 방향의 정확성은 현재 자동 점수에 포함되지 않는다. 보고서 생성 여부만 기록하고, 근거 일치·원인 타당성·실행 가능성·검증 방법은 별도 사람 평가 대상으로 남긴다.

## 결과 파일

```text
.qa-evals/<UTC시각_실행ID>/
  manifest.json       # 세트/모델/반복/순서, 엔진 코드 해시와 버전, 평가자용 정답
  results.json        # 사례별 판정, 질문, 오류, 독립 검사와 근거 경로
  results.csv         # 비교·발표용 표
  model_calls.json    # 호출 상태·모델·토큰·시간; 프롬프트·키는 저장하지 않음
  summary.json        # 명시적인 분자·분모와 완료 여부
  summary.md          # 한국어 결과표와 근거 링크
  trials/
    <사례ID_반복>/
      <엔진작업ID>/   # 제보 이미지 준비, QA, 독립 검사 각각의 기록
```

디렉터리와 파일은 비공개 권한으로 생성하고 `.qa-evals/`는 Git에서 제외한다. 예외는 코드/종류/발생 위치만 기록하고 공급자 예외 본문이나 API 키는 저장하지 않는다. Markdown 보고서의 상대 링크를 유지하려면 전체 실행 디렉터리를 함께 보관한다.

`manifest.json`의 사례 정답은 평가자용이다. 모델 요청에 합치거나 테스트 페이지에 표시하지 않는다. 모델에 제공되는 데이터에는 사용자 제보의 증상 설명은 남아 있어야 한다. 평가용 정답 제거와 제보 정보 삭제는 다른 작업이다.

## 코드 구성

- `core_engine.evaluation.cases`: 12개 사례·보고 텍스트·평가기용 reference plan.
- `core_engine.evaluation.site`: 중립 화면과 서버 내부 버전 전환·독립 검사.
- `core_engine.evaluation.fixture_model`: 명시적인 고정 응답. AI 성능 평가에 사용하지 않음.
- `core_engine.evaluation.grading`: 채점·분모·지표·한국어 요약.
- `core_engine.evaluation.runner`: 순차 실행·호출 제한·증거 저장·CLI.

자동 테스트에는 실제 API 호출을 넣지 않는다. 정상/버그 쌍의 제보 이미지 일치, 정답 메타데이터의 모델 입력 제외, 잘못된 절차의 거절, 환경 오류 구분, 누락 사용량과 호출 한도, 전체 고정 모델 흐름을 검증한다.

# 두 번째 모델을 검토자로 쓰는 제안

2026-11-05 기준 설계 제안이다. 현재 엔진에는 두 번째 공급자 연결이나 모델 간 토론 실행이 들어 있지 않다. 이번 개선은 기존 모델의 계획 작성·검증을 보강하고 동일 평가로 비교한다.

## 역할

첫 모델은 제보 해석과 재현 계획을 작성한다. 두 번째 모델은 근거 없는 가정, 누락된 재현 조건, 잘못 선택한 검사 대상, 정상·버그 조건의 뒤바뀜을 검토한다. 무조건 반대하도록 지시하지 않으며 구체적인 결함을 찾지 못하면 통과시킨다. 브라우저에서 확인하지 않은 원인을 확정해서도 안 된다.

권장 흐름은 `계획 작성 → 프로그램 검증 → 비판 모델 검토 1회 → 필요한 경우 계획 수정 1회 → 프로그램 재검증 → 계획 고정 → 브라우저 실행 → 근거 보고`다. 두 모델의 합의는 재현 증거가 아니다. 실제 실행 판정은 기존의 결정적 검사와 반복 관찰로 유지한다.

검토 모델은 제보 원문, 정제된 화면 요소, 계획, 관련 근거 참조만 받는다. 평가 정답과 독립 채점 결과는 받지 않는다. 출력은 `accept / revise / needs_info`와 문제 필드, 근거 참조, 확인할 반례로 제한한다. 자유로운 도구 실행, 임의 범위 확대, 실행 후 정답에 맞춰 판정 조건을 바꾸는 것은 허용하지 않는다.

예를 들어 “완료 조건이 정상 결과와 같으므로 버그 화면에서 끝나지 않는다”, “입력값이 제보에 없다”, “잘림을 글자 내용 비교로 확인하고 있다”는 구체적인 지적이다. 형식으로 확실히 판별할 수 있는 문제는 현재 추가한 프로그램 검증이 먼저 처리한다.

## 무료 API 후보

| 후보 | 사용할 역할 | 확인할 조건 |
|---|---|---|
| Groq의 `openai/gpt-oss-120b` | 제보·DOM 요약·계획을 읽는 텍스트 검토 | 텍스트 입출력 모델. 무료 플랜의 계정별 모델 접근·호출 한도 확인 |
| Gemini API의 무료 티어 모델 | 화면까지 함께 보는 검토 | 모델별 무료 지원 범위와 입력 데이터 취급 조건 확인 |

Groq는 무료 티어를 제공하며, `gpt-oss-120b` 문서에는 텍스트 입출력과 JSON Schema 지원이 안내되어 있다. 정확한 한도는 계정별로 확인해야 한다. 이 프로젝트의 검토 품질은 아직 측정하지 않았다. [Groq 요금제 안내](https://console.groq.com/docs/billing-faqs), [모델 문서](https://console.groq.com/docs/model/openai/gpt-oss-120b), [호출 한도](https://console.groq.com/docs/rate-limits).

Gemini 무료 티어는 일부 모델의 무료 입출력을 제공한다. 공식 가격 페이지는 무료 티어의 콘텐츠가 제품 개선에 사용될 수 있다고 명시한다. 고객사 데이터를 다루는 서비스이므로 무료 실험에는 합성 제보를 사용하고 실제 고객 데이터 전송 조건은 별도로 결정해야 한다. [Gemini API 가격·데이터 사용 조건](https://ai.google.dev/gemini-api/docs/pricing).

## 효과를 검증하는 방법

1. 현재 개선된 단일 모델을 기준으로 고정한다.
2. 같은 모델이 자기 계획을 한 번 더 검토하는 조건과, 다른 모델이 한 번 검토하는 조건을 비교한다. 추가 호출 자체의 효과와 두 번째 모델의 효과를 구분한다.
3. 제보·실행 환경·판정 기준·최대 호출 수를 고정하고 순서를 섞는다. 기존 개발 사례와 별도로 준비한 사례를 나눠 보고한다.
4. 재현·정상 판정·추가 질문·환경 오류뿐 아니라 잘못된 반박으로 정상 계획을 망친 비율, 판정 보류, 시간, 두 공급자의 토큰을 함께 기록한다.
5. 검토 모델이 실패하거나 한도를 넘으면 검토 미완료 상태를 기록한다. 실패한 검토를 합의나 품질 향상으로 집계하지 않는다.

이 방식이 더 나을 가능성은 있지만, 현재 프로젝트에서 성능이 좋아진다고 입증된 것은 아니다. 먼저 비교 실험으로 개선 폭과 추가 비용을 확인한 뒤 기본 기능으로 켜는 것이 적절하다.
